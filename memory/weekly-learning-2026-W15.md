## 🔧 技术学习

### 1. Firecrawl 自部署踩坑记录

**问题**: 尝试自部署 Firecrawl 失败，容器反复重启

**根本原因**:
- Firecrawl 容器设计依赖外部服务自动初始化数据库表结构
- 但实际容器镜像内没有实现自动迁移逻辑
- 环境变量 `NUQ_RUN_MIGRATIONS` 和 `RUN_MIGRATIONS` 均无效
- 容器内缺少 `package.json`、Prisma schema 等迁移必需文件

**经验教训**:
- 自部署开源项目前必须先仔细阅读官方文档
- 查看 GitHub Issues 了解常见部署问题
- 折腾 2 小时无果时，考虑 hosted 版本可能更高效

**替代方案**: 使用官方 hosted 服务 (firecrawl.dev)

### 2. 周期性任务状态跟踪

**问题**: 基金日报每天重复发送多次

**解决方案**:
- 创建状态跟踪文件 `memory/fund-report-state.json`
- 记录最后发送日期，每次发送前检查
- 只有日期变更时才发送新日报

**代码模式**:
```json
{
  "lastReportDate": "2026-04-09",
  "lastReportTimestamp": 1744198800000
}
```

**应用场景**: 所有周期性任务（日报、周报、定时备份等）都需要状态跟踪

### 3. 模型配置完整性

**问题**: 图片识别服务调用失败

**原因**: Qwen3.5-Plus 模型配置未声明视觉输入支持

**修复**: 更新 `models.json` 添加完整能力声明
```json
{
  "model": "qwen/qwen3.5-plus",
  "input": ["text", "image"],  // 关键：声明支持图片输入
  "output": ["text"]
}
```

**经验**: 模型配置必须完整声明输入/输出能力，否则工具调用会被拒绝
