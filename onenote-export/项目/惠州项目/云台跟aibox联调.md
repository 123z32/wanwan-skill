云台跟aibox联调
 
 
 
 
 

 
这是为你整理的惠州项目云台控制与 AI Box 联调核心笔记。你可以直接将这些内容记录到你的项目文档或交接手册中，涵盖了所有踩过的坑和定制化配置：

 
一、 运行环境与部署避坑指南

 
 
- 
绝不能在 PyCharm 中点击运行：

 
 
- 现象：在 PyCharm 中运行会导致长达 10 秒的严重指令和视频流延迟，而纯命令行下仅需 1 秒。
 
- 原因：PyCharm 的虚拟控制台渲染阻塞了主线程，且 IDE 的快捷键监听与代码底层的全局键盘 Hook 产生了严重冲突。
 
- 规范操作：代码修改保存后，必须在外部打开系统的 CMD 黑窗口，使用 python main.py 命令独立运行。
 

 
 
- 
多 Python 环境依赖安装：

 
 
- 如果出现明明 pip install 提示成功，但运行却报错 ModuleNotFoundError，说明装错了环境。
 
- 必须使用 python -m pip install requests pynput 命令，强制将依赖安装到当前正准备执行的 Python 环境中。
 

 
 

 
二、 AI Box 视频流与控制台并发冲突解决（核心重点）

 
 
- 
防止 Session 互踢（控制失效）：

 
 
- 控制脚本（发 HTTP 指令）和 AI Box（拉 RTSP 视频流）严禁使用同一个 admin 账号。
 
- 操作：登录摄像机 Web 后台，新建一个只读权限的账号（如 aibox），专门给边缘计算盒子拉流使用，admin 账号留给 Python 键盘控制台独占。
 

 
 
- 
视频流去延迟极限优化：

 
 
- 摄像机端：后台改用子码流（Sub-stream）、H.264 编码，并将 I 帧间隔（GOP）缩短至与帧率一致。
 
- AI Box 代码端（OpenCV）：拉流代码必须加上一行强行清空缓存的指令，拒绝底层排队：cap.set(cv2.CAP_PROP_BUFFERSIZE, 1)。
 

 
 

 
三、 定制化机芯特殊控制逻辑（硬件对接文档）

 
这台摄像机的固件有特殊的非标控制逻辑，开发或维护时需特别注意：

 
 
- 
反常规的开关逻辑：

 
 
- 常规摄像机是“设置=开，调用=关”，但此机芯的逻辑是反转的：“调用（Run）= 开启，设置（Set）= 关闭”。
 

 
 
- 
灯光复用预置位绑定：

 
 
- 白光灯：与 36 号预置位绑定。代码中按 I 键时，发送 Run 36 为开灯，Set 36 为关灯。
 
- 红外灯（彩转黑）：与 56 号预置位绑定。代码中按 O 键时，发送 Run 56 为开灯，Set 56 为关灯。
 

 
 
- 
巡航防干扰隔离：

 
 
- 本地加载坐标路线文件时，代码会自动过滤剔除 36 和 56 这两个点位，防止夜间自动巡航时触发“爆闪”乱象。
 

 
 
- 
雨刷控制：

 
 
- 未走通用外设通道，而是严格按照协议采用独立的 setWiper 方法发送 JSON。
 

 
 

 
四、 现场操作人员快捷键手册

 
 
- 云台移动：W (上) / S (下) / A (左) / D (右)
 
- 镜头缩放：Q (拉近变倍) / E (推远广角)
 
- 电机调速：R (动态提速 +15) / F (动态减速 -15) ，当前速度会在屏幕实时显示。
 
- 
机芯外设：

 
 
- U：切换雨刷开关
 
- I：切换白光灯开关
 
- O：切换红外灯（彩转黑）开关
 

 
 
- 
巡航与点位：

 
 
- 1~9：录制当前位置为预置点
 
- P：一键开启 / 停止自动巡航（需至少录制2个点）
 

 
 
- 
本地路线管理：

 
 
- K：保存当前录制的路线至本地（保存在 routes 文件夹，自动转 JSON）
 
- L：扫描并加载本地路线文件
 

 
 
- 安全退出：ESC 键平滑退出程序。
 

 

 
route add 192.168.123.0 mask 255.255.255.0 192.168.1.32 -p
