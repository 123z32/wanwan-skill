端到端网络互通的三大基石：子网划分、静态路由与防火墙规则
 
 
 
 
 

 
一、 子网掩码与逻辑寻址边界 (Subnetting & Logical Boundary)

 
📝 学术化理论

 
在 TCP/IP 网络模型中，子网掩码（Subnet Mask）用于界定逻辑网络的边界。通过将 32 位的主机 IP 地址与子网掩码进行**按位逻辑与（Bitwise AND）**运算，底层网络栈能够提取出该设备的网络前缀（Network Prefix）。 如果通信双方经过计算得出相同的网络前缀，则判定二者处于同一个二层广播域（局域网）内，数据帧将直接通过 MAC 地址在数据链路层（L2）完成交付；若网络前缀不同，则必须将数据包向上层递交至默认网关（Default Gateway），进行三层（L3）路由转发。

 
🌰 易懂的例子 (以机械狗内部网络为例)

 
假设你给机械狗内部的 STM32 主控板分配了 IP 192.168.10.10，给负责双光融合的相机模块分配了 IP 192.168.10.20，它们的子网掩码都是 255.255.255.0。

 
 
- 计算过程： 它们的前三段 192.168.10 经过掩码计算后完全一致。
 
- 实际表现： 这意味着 STM32 和双光相机在同一个“车间”里。STM32 想要调取相机的画面时，不需要经过外面的 5G CPE，数据直接在狗内部的微型交换机上就完成了互传，速度极快且不占外网带宽。
 

 
(简单来说就是通过子网掩码判断是不是在同一个局域网内，常用的子网掩码都是 255.255.255.0)

 
二、 静态路由表与最长前缀匹配 (Static Routing & LPM Algorithm)

 
📝 学术化理论

 
路由（Routing）是三层网络设备（路由器、多层交换机）为跨网段数据报文选择最佳转发路径的决策过程。静态路由表（Static Route）是由网络管理员手动注入路由信息库（RIB）的确定性转发规则。 当路由器收到数据报文时，会提取其目的 IP 地址，并运用**最长前缀匹配算法（Longest Prefix Match, LPM）**在路由表中进行检索。路由器将选择匹配度最高（掩码最长、指向最精确）的表项，将报文引流至对应的下一跳（Next-Hop）地址。

 
1. 静态路由表项的关键结构 一条完整的静态路由表项通常包含以下参数：

 
 
- 目的网络 (Destination Network): 数据报文期望到达的目标逻辑网段。
 
- 子网掩码 (Subnet Mask): 界定目的网络前缀长度的匹配依据。
 
- 下一跳 (Next-Hop): 数据报文离开本地设备后，到达相邻网络节点的入口 IP 地址（必须是二层直连可达的地址）。
 
- 出接口 (Outbound Interface): 本地设备转发该数据包的物理或逻辑接口。
 

 
2. 缺省路由 (Default Route / Route of Last Resort) 特指目的网络为 0.0.0.0 且掩码为 0.0.0.0（记为 0.0.0.0/0）的静态路由。它是前缀长度最短的路由，充当 LPM 匹配算法中的最后一道兜底机制，用于转发所有未匹配到明细路由项的未知数据报文。

 
🌰 易懂的例子 (以 SCADA 下发控制指令为例)

 
假设项目方的内网是一张非常庞大且复杂的网络，而你的机械狗身处在 5G 专网（网段为 10.10.1.x）中。

 
 
- 场景： 内网的 SCADA 服务器想要给机械狗下发一条“紧急停机”的指令。
 
- 路由决策： 数据包从 SCADA 服务器发出，来到了内网的核心交换机（路由器）。交换机就像一个十字路口的交警，它拿着数据包上的目标地址 10.10.1.5，去查自己的工作手册（路由表）。
 
- 静态路由规则： 手册上写着一条静态路由：“凡是去往 10.10.1.x（5G 专网）的车，请统一开往 192.168.1.254（连接 5G 网络的那个出口网关）”。于是，交警准确地把指令丢给了出口网关，指令最终顺利通过 5G 基站传达给了机械狗。如果没有这条手动写上去的静态路由，交警不知道路，这个指令包就会被直接丢弃。
 

 
（就是不同网段的设备需要通过交换机，交换机查询路由表，找到跳转到该网段的网关，然后该网关在给设备通信。）

 

 
三、 防火墙包过滤与五元组访问控制 (Packet Filtering & Five-Tuple Access Control)

 
📝 学术化理论

 
防火墙的访问控制列表（ACL）是对跨越网络安全边界的数据流进行细粒度鉴权的机制。在严苛的工业网络环境中，防火墙通常采用**隐式拒绝（Implicit Deny）**的安全基线策略，即拦截所有未被显式允许的流量。

 
合法流量的放行依赖于对网络五元组的精准匹配。五元组集合定义为：

 ![图片](https://graph.microsoft.com/v1.0/users('2209338213@qq.com')/onenote/resources/0-2f562bb16c50490bb1f9d5d0598bdc3a!1-9E53C6D99C1E5AD1!sc7d3a8c09a9e4a28b94e95296b56457a/$value)
 
在申请放行规则时，必须精确指定这五个变量。例如：允许源端为 5G CPE (Src_IP)、通过 UDP 协议 (Protocol)、向内网 AI Box (Dst_IP) 的 554 端口 (Dst_Port) 发起单向数据流。

 
只有当传入数据报文的这五个属性与防火墙预设的“白名单（Permit Rule）”完全咬合时，数据才被允许穿透安全边界。

 
🌰 易懂的例子 (以双光相机推流给 AI Box 为例)

 
电厂机房（内网）的安全级别极高，就像一个戒备森严的金库，默认不准任何人进出（隐式拒绝）。你的 5G CPE 在金库外面，想要把狗子的视频流发给金库里的 AI Box。

 
 
- 场景： 机械狗开始向内网的 AI Box 发送 UDP 视频流。
 
- 遭遇拦截： 视频流数据包刚走到内网机房大门口，就被防火墙保安拦住了。
 
- 
五元组白名单通行证： 为了让视频流进去，你需要让项目方网管在保安的“白名单”上加一行非常精确的记录：

 
 
- 源 IP (谁发的)： 必须是你的 5G CPE 的 IP。
 
- 目的 IP (发给谁)： 必须是 AI Box 的 IP。
 
- 协议 (怎么发)： UDP 协议。
 
- 目的端口 (进哪个门)： 554 端口（RTSP视频流专用）。
 
- (源端口通常为随机，可视策略放宽)。
 

 
 
- 实际表现： 保安（防火墙）核对这五条信息（五元组），发现完全匹配，这才会拉开闸门放行。如果是别的 IP 冒充，或者用 TCP 协议想硬闯，都会被直接丢弃。
 

 
（就是做一个防火墙跟白名单，源IP，目的IP，协议号，目的端口，源端口完全正常，数据才能流出）
