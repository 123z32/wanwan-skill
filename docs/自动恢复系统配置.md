# 🛡️ 自动恢复系统配置文档

*最后更新：2026-04-01*

---

## 📋 概述

本系统提供 OpenClaw Gateway 的自动监控和恢复功能，确保服务持续可用。

**核心功能：**
- ✅ Gateway 进程监控（每分钟检查）
- ✅ 自动重启（崩溃后 10 秒内重启）
- ✅ Git 恢复（重启失败时从 GitHub 恢复配置）
- ✅ 健康检查（每 5 分钟全面检查）
- ✅ 日志记录（所有操作记录到日志文件）

## 🔧 工作原理

### 1. Supervisor 守护进程

**脚本**: `scripts/supervisor.sh`

**功能**:
- 启动/停止/重启 Gateway
- 保存 PID 到文件（`/tmp/openclaw-gateway.pid`）
- 提供状态查询

**命令**:
```bash
bash scripts/supervisor.sh start    # 启动
bash scripts/supervisor.sh stop     # 停止
bash scripts/supervisor.sh restart  # 重启
bash scripts/supervisor.sh status   # 状态
bash scripts/supervisor.sh monitor  # 后台监控模式
```

---

### 2. 健康检查守护进程

**脚本**: `scripts/healthcheck-daemon.js`

**功能**:
- 每 5 分钟检查一次系统状态
- 检查项目：Gateway 进程、磁盘空间、内存
- 发现 Gateway 异常时触发自动恢复

**配置**:
```javascript
const CHECK_INTERVAL = 5 * 60 * 1000; // 5 分钟
```

**启动**:
```bash
nohup node scripts/healthcheck-daemon.js > logs/healthcheck-daemon.log 2>&1 &
echo $! > /tmp/openclaw-healthcheck.pid
```

---

### 3. 自动恢复脚本

**脚本**: `scripts/auto-heal.sh`

**恢复流程**:

```
1. 检查 Gateway 进程
   ├─ 存在 → ✅ 系统正常
   └─ 不存在 → 进入恢复流程

2. 检查网络连通性（GitHub）
   ├─ 不可用 → 等待 30 秒，重试
   └─ 可用 → 继续

3. 尝试重启 Gateway
   ├─ 成功 → ✅ 恢复完成
   └─ 失败 → 进入下一步

4. 从 Git 恢复配置（第 2 次失败后）
   ├─ 重置到最新：git reset --hard origin/main
   ├─ 或重新克隆：git clone <remote>
   └─ 重启 Gateway

5. 最大重试 3 次，全部失败 → ❌ 报告失败
```

**日志位置**: `logs/auto-heal.log`

## 🛠️ 故障排查

### 问题 1: Gateway 无法启动

**症状**: `bash scripts/supervisor.sh start` 失败

**排查步骤**:
```bash
# 1. 查看日志
tail -f logs/gateway.log

# 2. 检查配置
openclaw config validate

# 3. 检查端口占用
ss -tlnp | grep 18789

# 4. 手动启动测试
openclaw gateway
```

**解决方案**:
```bash
# 清理残留进程
pkill -f openclaw-gateway

# 清理端口
kill $(lsof -t -i:18789) 2>/dev/null || true

# 重新启动
bash scripts/supervisor.sh start
```

---

### 问题 2: 健康检查守护进程退出

**症状**: `ps aux | grep healthcheck-daemon` 无结果

**排查步骤**:
```bash
# 1. 查看日志
tail -f logs/healthcheck-daemon.log

# 2. 检查 Node.js
node --version

# 3. 手动运行测试
node scripts/healthcheck-daemon.js
```

**解决方案**:
```bash
# 重新启动守护进程
nohup node scripts/healthcheck-daemon.js > logs/healthcheck-daemon.log 2>&1 &
echo $! > /tmp/openclaw-healthcheck.pid
```

---

### 问题 3: Git 恢复失败

**症状**: `logs/auto-heal.log` 显示 "Git fetch 失败"

**排查步骤**:
```bash
# 1. 测试网络
curl -I https://github.com

# 2. 检查 Git 配置
cd /home/node/.openclaw/workspace
git remote -v

# 3. 手动测试 Git
git fetch origin
```

**解决方案**:
```bash
# 重新配置远程仓库
cd /home/node/.openclaw/workspace
git remote set-url origin https://github.com/123z32/wanwan-skill.git
git fetch origin
```

## 📈 性能优化

### 调整检查频率

编辑 `scripts/healthcheck-daemon.js`:

```javascript
// 默认 5 分钟
const CHECK_INTERVAL = 5 * 60 * 1000;

// 改为 1 分钟（更频繁）
const CHECK_INTERVAL = 1 * 60 * 1000;

// 改为 10 分钟（减少资源占用）
const CHECK_INTERVAL = 10 * 60 * 1000;
```

### 调整重试次数

编辑 `scripts/auto-heal.sh`:

```bash
# 默认 3 次
MAX_RETRY=3

# 增加重试次数（更激进）
MAX_RETRY=5

# 减少重试次数（更快失败）
MAX_RETRY=2
```

## 🔒 安全注意事项

### 1. Git 认证

当前使用 HTTPS 公开仓库，无需认证。如果使用私有仓库：

```bash
# 配置 Git 凭证
git config --global credential.helper store

# 或使用 SSH
git remote set-url origin git@github.com:123z32/wanwan-skill.git
```

### 2. 日志轮转

防止日志文件过大：

```bash
# 添加到 healthcheck-daemon.js
const MAX_LOG_SIZE = 10 * 1024 * 1024; // 10MB

// 检查日志大小并轮转
if (fs.existsSync(LOG_FILE) && fs.statSync(LOG_FILE).size > MAX_LOG_SIZE) {
    fs.renameSync(LOG_FILE, LOG_FILE + '.old');
}
```
