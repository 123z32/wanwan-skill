## 🔴 错误 1: GPIO 占用

### 现象
```
2026-03-21 15:06:20 - WARNING - ⚠️  GPIO 初始化失败：[Errno 16] Opening output line handle: Device or resource busy
```

### 原因
- `gpio_http_service.py` 正在运行，占用了 GPIO 17
- 旧的服务进程未停止

### 解决方案
```bash
# 启动前停止所有占用 GPIO 的服务
sudo pkill -f gpio_http_service.py
sudo pkill -f gpio_modbus_service.py
sudo pkill -f modbus_slave.py
sleep 2  # 等待 GPIO 释放

# 启动新服务
sudo python3 gpio_led_light_modbus_service.py
```

### 经验教训
✅ **启动前必须清理旧进程**  
✅ **同一 GPIO 引脚只能被一个程序使用**

## 🔴 错误 3: LabVIEW 错误 538 (Transaction ID 不匹配)

### 现象
```
错误 538193 发生于 IP Data Unit.lvclass:Read ADU Packet.vi:5030001
```

**具体表现**:
- 开关低电平时不报错
- 开关高电平或电平变化时报错
- 报错后无法读取 LED 和光敏电阻数据

### 根本原因

**Modbus TCP 响应帧的 Length 字段计算错误！**

#### 错误的响应帧 (Length = 4)
```
写单个线圈响应：
┌──────┬──────┬──────┬──────┬──────┬──────┐
│Trans │Proto │Length│Unit  │ FC   │ Data │
│ ID   │  ID   │ = 4  │  ID  │ = 05 │      │
├──────┼──────┼──────┼──────┼──────┼──────┤
│ 2 字节 │ 2 字节 │ ❌   │ 1 字节 │ 1 字节 │ 4 字节 │
│      │      │      │      │      │(地址 + 值)│
└──────┴──────┴──────┴──────┴──────┴──────┘

实际 Length 应该是：1 + 1 + 4 = 6 字节
```

#### 正确的响应帧 (Length = 6)
```
写单个线圈响应：
┌──────┬──────┬──────┬──────┬──────┬──────┐
│Trans │Proto │Length│Unit  │ FC   │ Data │
│ ID   │  ID   │ = 6  │  ID  │ = 05 │      │
├──────┼──────┼──────┼──────┼──────┼──────┤
│ 2 字节 │ 2 字节 │ ✅   │ 1 字节 │ 1 字节 │ 4 字节 │
│      │      │      │      │      │(地址 + 值)│
└──────┴──────┴──────┴──────┴──────┴──────┘

正确 Length: 1 (Unit ID) + 1 (FC) + 4 (Data) = 6 字节
```

### 为什么低电平不报错？

**推测原因**:
- 低电平写操作 (`0x0000`) 时，LabVIEW 可能容忍了 Length 错误
- 高电平写操作 (`0xFF00`) 时，LabVIEW 解析响应发现数据异常
- Length=4 导致 LabVIEW 读取的字节数不足
- Transaction ID 偏移，读取到错误的数据
- 报错 538："Response Transaction ID doesn't match Request"

### 修复代码

**修复前** (❌ 错误):
```python
# 功能码 05: 写单个线圈
response = bytearray()
response.extend(trans_id.to_bytes(2, 'big'))
response.extend(b'\x00\x00')
response.extend(b'\x00\x04')  # ❌ Length = 4 (错误！)
response.append(unit_id)
response.append(0x05)
response.extend(payload)
```

**修复后** (✅ 正确):
```python
# 功能码 05: 写单个线圈
response = bytearray()
response.extend(trans_id.to_bytes(2, 'big'))
response.extend(b'\x00\x00')
response.extend(b'\x00\x06')  # ✅ Length = 6 (正确！)
response.append(unit_id)
response.append(0x05)
response.extend(payload)  # 原样返回地址 + 值 (4 字节)
```

### 修复的功能码

| 功能码 | 操作 | 原 Length | 修复后 | 说明 |
|--------|------|----------|--------|------|
| `0x05` | 写单个线圈 | `4` ❌ | `6` ✅ | Unit ID(1) + FC(1) + Data(4) |
| `0x06` | 写单个寄存器 | `4` ❌ | `6` ✅ | Unit ID(1) + FC(1) + Data(4) |
| `0x0F` | 写多个线圈 | `4` ❌ | `6` ✅ | Unit ID(1) + FC(1) + Addr(2) + Qty(2) |
| `0x10` | 写多个寄存器 | `4` ❌ | `6` ✅ | Unit ID(1) + FC(1) + Addr(2) + Qty(2) |

### 经验教训
✅ **Modbus TCP Length 字段 = Unit ID + FC + Data 的字节数**  
✅ **写操作响应必须原样返回请求中的数据**  
✅ **Transaction ID 必须严格匹配**

## 🔴 错误 4: 读数据失败 (高电平时无数据)

### 现象
- 开关低电平：可以正常读取 LED 和光敏数据
- 开关高电平：布尔数组变无数据状态
- 从低电平变高电平：读取不到数据

### 根本原因

**写线圈后未同步更新离散输入 (`store["di"]`)**

#### 错误的数据流
```
LabVIEW → 写线圈 0x0000 = 1 (LED ON)
    ↓
store["co"][0] = True  ✅ (线圈更新)
    ↓
led.write(True)  ✅ (硬件控制)
    ↓
store["di"][0] 还是 False  ❌ (离散输入未更新！)
    ↓
LabVIEW → 读离散输入
    ↓
返回 [False, ?]  ❌ (错误数据)
```

### 修复方案

**写操作后立即同步更新离散输入**

```python
# 功能码 05: 写单个线圈
elif fc == 0x05:
    addr = int.from_bytes(payload[0:2], 'big')
    value = int.from_bytes(payload[2:4], 'big')
    store["co"][addr] = (value == 0xFF00)
    
    # ⭐ 立即控制 LED 并同步更新离散输入
    if addr == 0:
        if led:
            led.write(store["co"][0])      # 控制硬件
            actual = led.read()            # 读取实际状态
            store["di"][0] = actual        # ⭐ 同步更新离散输入
            logger.info(f"[{timestamp}] LED: {state_str} | GPIO: ✓")
        else:
            # 模拟模式
            store["di"][0] = store["co"][0]  # ⭐ 同步更新
            logger.info(f"[{timestamp}] LED: {state_str} (模拟)")
```

### 修复后的数据流
```
LabVIEW → 写线圈 0x0000 = 1 (LED ON)
    ↓
store["co"][0] = True  ✅
    ↓
led.write(True)  ✅
    ↓
actual = led.read()  ✅
    ↓
store["di"][0] = actual  ✅ ⭐ (立即同步！)
    ↓
LabVIEW → 读离散输入
    ↓
返回 [True, 光敏状态]  ✅ (正确数据)
```

### 经验教训
✅ **写线圈后必须同步更新离散输入**  
✅ **store["co"] 和 store["di"] 要保持一致**  
✅ **模拟模式也要同步更新**
